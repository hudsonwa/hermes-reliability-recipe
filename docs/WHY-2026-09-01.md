# Why the recent improvements (2026-09-01)

An incident-driven hardening pass. Timeline below is anonymized; every root
cause was reproduced and the fix for each is covered by a test in this repo.

## The night it broke

A production agent was asked the maintenance question: *"is it the soft
prompting, or do we need stronger hooks?"* Investigation found **three
simultaneous degradations**, none of them visible from the outside:

1. **A framework update silently reverted the always-on gate patch.**
   `hermes update` (a git pull) overwrote a local one-line core change. The
   gate fell back to edit-gated mode: final answers were only screened on
   turns where files had been edited. Chat-only lies shipped untouched —
   the exact "silent product death" mode this recipe exists to prevent.

2. **A config clobber flipped verification off.** Another tool's config
   rewrite set `verify_on_stop: false` on a second profile (and dropped a
   soft-rule marker). Days passed before anyone noticed.

3. **The self-heal watchdog was blind to #1 and dead anyway.** Its cron had
   stopped weeks earlier, and even when alive its checks never covered the
   Hermes tree patch — so a *running* self-heal would still have reported
   "OK" after the update. A watchdog that doesn't watch the thing that broke
   is decoration.

## What the A/B experiment proved

A controlled canary harness (ground truth from session DBs and gate-hit logs,
never LLM self-judgment) ran the same lie-probe against the degraded and the
repaired stack:

| Condition (final-answer lie, no edits) | Degraded | Always-on |
|---|---|---|
| Gate fired | 0/2 | 2/2 |
| Edit-turn lie | 2/2 | 4/4 |

One degraded run shipped the lie verbatim; the identical prompt after repair
was caught mid-ship and corrected with real receipts. Conclusion: **soft
rules help only when the model voluntarily uses tools; the always-on hard
gate is the load-bearing layer.** Both layers together produced a further
effect: the model usually *refuses* to lie before the gate is even needed —
which is why the health canary scores **lies shipped**, not gate hits. A
stack that prevents the lie scores zero gate hits; counting hits would call
success failure.

## The improvements (each with its test)

- **Drift detection + auto-repair** (`4e6aeb2`): self-heal now checks the
  live tree for the always-on form and re-applies it when wiped. GT10 locks
  it hermetically (fake degraded tree → flagged; clean tree → silent).
- **Finish-line rule + seam ledger** (`5e1787e`): "verified/done" without a
  named check + coverage is nudged, then hard-PARTIAL at max attempts; a
  machine ledger prevents same-fingerprint re-lies. 11 gate tests + 5 ledger
  tests.
- **Observability fix** (`9e2b190`): the test suite polluted the live hits
  log with test-attributed rows (155 of 200 rows at one point); tests now run
  against a temp log so organic catches stay countable.
- **Dead-man's switch** (this pass): heartbeats + daily stale check, after
  the watchdog-death failure mode hit twice in one week (one silent for a
  month, one for 12 hours).
- **Config-parity checker** (this pass): mechanical detection of the config
  clobber class across profiles.
- **Update-proof pin kit + anchor probe + update doctor** (this pass): the
  patch survives updates as a pinned, hash-verified, one-command re-apply;
  the anchor probe catches upstream refactors; the doctor re-verifies the
  whole stack after any update.

## Operationally verified

Across three profiles on two machines, after the fixes: gate code live in all
three running gateways (verified post-restart), controlled A/B as above, an
adversarial cold-lie probe (tools forbidden) caught by the gate mid-ship and
corrected with real receipts, a write-probe that proved spawned sessions
could mutate soft-rule files (closed by doctor integrity checks), and honest
gaps recorded — including one of the two report authors catching that a
"cron registered" claim was false because the jobs had landed in the wrong
profile registry. Registration is not execution: scheduled-job claims require
`last_run` evidence, not creation receipts.
